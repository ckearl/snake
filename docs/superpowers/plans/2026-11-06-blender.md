# Blender Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play any set of the ten game modes at once ("Blender"), chosen from a pop-up at the end of the game mode row.

**Architecture:** `state.modes` (a Set) replaces the single mode for every rule check; `state.mode` stays as the blend's key string (`'classic'`, `'box'`, `'box+key'`) for high scores. Fruit "slots" are built by one `spawnSlot()` that walks the wrapping order (Keys → Box → fruit → Shields, Portal pairs innermost, Poison decoys beside), and a revealed fruit is dressed by one `dressFruit()` (flight, shields). On-eat effects run in one `onEat()` in the design's fixed order; flying catches queue their effects for the next tick.

**Tech Stack:** Plain ES modules, no build step, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-06-blender-design.md` (plus the answers in `docs/superpowers/blender-overnight-prompt.md`).

## Global Constraints

- No new dependencies, no build step. Rules in `src/game.js`, drawing in `src/render.js`, wiring/UI in `src/main.js`.
- `npm test` passes after every commit (127 tests at the start).
- Single-mode play behaves exactly as today; existing saved `snake.mode` and `snake.best.<size>.<mode>` keys keep working.
- High score key for a blend: `snake.best.<size>.<modes sorted, joined by '+'>`.
- Commits authored by the repo user only, no trailers. Branch `blender`, no push.
- Pixel art, gentle and subtle animation.

## Review Focus

- A saved blend containing a mode id that no longer exists → dropped silently on load, never a crash.
- Box in a blend with fruit count > 1 → one box + target per slot, each box only opens on its own target.
- Flying fruit with walls touching the head from behind (head not moving toward it) → bounces, not a death.
- Poisoned wander inside a mine field at its 3rd move → must leave the field.
- Chat drops (`!box`, `!key`, `!portal`, …) inside a blend → stay plain bonus pieces, never counted as slots.

### Task 4: Movement in blends

**Produces:** flyer kinds `'winged' | 'magnet' | 'both'`; `state.caught` (fruits caught since the last step, on-eat effects pending); `updateFlyers` returns caught fruits and may set `state.status = 'over'` (walled side) with `state.shieldHit`.

### Task 5: Wrapping order (slots)

**Files:** `src/game.js`; Test `test/blender.test.js`

**Produces:** `spawnSlot(state) -> boolean`, `dressFruit(state, f) -> f`, `slotsInPlay(state) -> number`, `slotOf(piece) -> string`; `spawnKeyPair(state, { bonus, pick, box, portal })`.

- Keys+Box: lock (placed like a box: clear ring, plus keepsBoardOpen), target (≥2 from lock), key; all share `slot`. Unlock puts a box with id `lock.box` on the lock square.
- Keys+Portal (no Box): two locks, one shape and id, one key; unlocking reveals a linked pair.
- Box+Portal: release puts one end on the target and the twin on a free square ≥ SPAWN_CLEARANCE from the head.
- Box in a blend respects the fruit count (one box + target per slot); single Box stays at one.
- Walls avoid box rings and targets (when Box is on); flags avoid boxes, targets, keys, locks; fields avoid box rings/targets (Box on); a box pushed onto a flag, lock or key bumps.
- Refill: fixed count tops slots up to the count; random drops a batch when no slot is left; a decoy eaten in a fixed count is replaced by a decoy.
- [ ] Tests for each bullet + every single mode's existing tests still pass; commit.
